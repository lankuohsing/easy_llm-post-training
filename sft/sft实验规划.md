# SFT 实践实验规划

本文用于规划监督微调（Supervised Fine-Tuning，SFT）的实践路线。目标不是只训练出一个分数较高的模型，而是通过可复现、可解释的对照实验，回答以下问题：

- SFT 带来的收益究竟来自接口对齐、已有能力激发，还是新能力获得？
- 数据质量、数量、多样性和重复率分别有什么影响？
- 训练目标、参数更新方式和优化强度会怎样改变模型行为？
- 如何提升领域能力，同时尽量保持通用能力？
- 哪些问题适合 SFT，哪些问题更适合继续预训练、RAG、蒸馏或强化学习？

本文只记录实验规划。具体训练命令、数据处理代码和实验结果应在相应阶段逐步补充。

## 1. 优先级定义

| 优先级 | 含义 | 执行原则 |
| --- | --- | --- |
| P0 | 基础必做 | 后续实验依赖这些结论，必须优先完成 |
| P1 | 核心主线 | 直接回答 SFT 的主要实践问题 |
| P2 | 能力扩展 | 在主线稳定后研究更复杂的使用场景 |
| P3 | 后续专题 | 与 SFT 相邻，但需要单独建立理论和代码体系 |

优先级表示重要程度，阶段编号表示执行顺序。同一优先级的实验也应按照阶段依赖依次进行。

## 2. 总体路线

| 阶段 | 优先级 | 主题 | 核心产物 |
| --- | --- | --- | --- |
| 阶段 0 | P0 | 建立可信的训练与评测流水线 | 可复现的最小 SFT 闭环 |
| 阶段 1 | P0 | Base 模型到 Instruct 模型 | 数据规模、质量和多样性曲线 |
| 阶段 2 | P0 | SFT 目标函数与优化机制 | loss、学习率、训练轮数和参数更新方式的消融结论 |
| 阶段 3 | P1 | 单领域能力增强 | 领域内和领域外的泛化结果 |
| 阶段 4 | P1 | 领域增益与通用能力保持 | 领域收益与通用退化的 Pareto 前沿 |
| 阶段 5 | P2 | 多领域、多轮、工具与长上下文 | 更复杂场景下的 SFT 方法与边界 |
| 阶段 6 | P3 | 蒸馏与在线策略蒸馏 | 独立的蒸馏实验体系 |

推荐严格按照阶段 0 到阶段 4 推进。阶段 5 中的专题可以按兴趣选择，不必一次全部开展；阶段 6 暂不作为当前主线。

## 3. 所有实验共用的规范

### 3.1 模型选择

优先选择同时公开 Base 和 Instruct checkpoint 的同一模型家族，以减少 tokenizer、模型结构和预训练数据差异造成的干扰。

- 1.5B 或 3B：用于数据、loss mask、分布式训练和评测流程的冒烟测试。
- 7B 或 8B：用于完整实验矩阵和多随机种子实验。
- 14B：用于复现最重要的结论，检查结论能否跨模型规模成立。
- 32B：先进行少量 LoRA 实验，再根据显存、序列长度和并行策略决定是否全参数训练。
- 70B 及以上：不作为初期实验对象，避免算力成本限制实验迭代次数。

8 卡 H20 的价值应优先用于增加对照组、保存中间 checkpoint 和复现关键结论，而不是一开始就追求最大的模型规模。

### 3.2 固定变量

除非某个实验专门研究对应变量，否则应固定：

- Base checkpoint 和 tokenizer；
- chat template、特殊 token 和停止条件；
- 最大序列长度和截断策略；
- loss mask 规则；
- 有效 batch token 数和梯度累积方式；
- 训练数据的有效回答 token 数；
- 推理 prompt、解码参数和最大输出长度；
- 评测脚本及其版本。

数据规模优先使用有效回答 token 数描述，而不是只报告样本数量。相同样本数可能对应完全不同的训练信号总量。

### 3.3 通用对照组

根据实验主题，从以下对照组中选择必要配置：

- 未训练的起始 checkpoint；
- 不训练，仅使用 zero-shot 或 few-shot prompt；
- 官方 Instruct checkpoint；
- 使用通用指令数据继续训练相同 token 数的模型；
- 仅使用目标领域数据训练的模型；
- 领域知识任务中的 RAG 基线；
- 原始领域文本上的继续预训练基线。

官方 Instruct 模型适合作为参考，但不应被视为严格的实验上界，因为其训练数据和训练过程通常并不完全公开。

### 3.4 统一评测矩阵

每次核心实验至少同时评估以下方面：

| 评测维度 | 目的 | 示例 |
| --- | --- | --- |
| 目标能力 | 判断实验是否达到直接目标 | 数学正确率、代码通过率、领域问答准确率 |
| 邻近与分布外能力 | 判断是否真正泛化 | 跨数据源、跨难度、题目改写和组合任务 |
| 通用能力 | 检查能力跷跷板 | 知识、推理、数学、代码、中英文任务 |
| 指令遵循 | 区分会做题和会按要求做题 | IFEval、FollowBench、格式约束 |
| 行为指标 | 发现均分掩盖的问题 | 回答长度、语言漂移、拒答率、格式合法率 |
| 工程效率 | 比较实际性价比 | GPU-hours、峰值显存、吞吐和训练 token 数 |

客观任务优先使用确定性解码和可执行判定。开放式任务使用模型裁判时，应进行盲化、随机交换回答顺序，并抽样人工检查裁判偏差。

### 3.5 数据和统计要求

- 训练前冻结开发集和测试集，避免反复根据测试结果调整训练方案。
- 对训练数据和 benchmark 做精确匹配、近重复和语义重复检查。
- 合成数据的教师模型可能见过公开 benchmark，仍需警惕隐性污染。
- 首轮配置可以使用单个随机种子筛选，最终候选至少运行 3 个随机种子。
- 报告各个 benchmark 的原始分数和变化，不只报告一个加权总分。
- 对同一批测试题上的模型差异使用配对统计方法，并报告置信区间。
- 如果差异很小且置信区间跨过 0，应表述为尚未观察到可靠差异。

## 4. 阶段 0：建立可信的最小闭环

**优先级：P0。**

### 4.1 目标

在研究模型能力之前，先确认数据、模板、labels、loss mask、训练和评测没有实现错误。

### 4.2 实验内容

1. 使用小模型和几十条样本进行过拟合测试，确认 loss 能稳定下降。
2. 随机解码若干条 `input_ids`，逐 token 检查 labels 和 loss mask。
3. 确认 system、user、padding 等不需要监督的位置被正确屏蔽。
4. 确认 assistant 回答及结束 token 是否按设计参与损失。
5. 验证训练与推理使用相同的 chat template 和特殊 token。
6. 验证保存、加载、断点续训和 LoRA 合并流程。
7. 用一个小型 benchmark 跑通从 checkpoint 到最终结果表的完整评测流程。

### 4.3 完成标准

- 模型能够过拟合小样本，并按目标格式生成回答；
- 人工检查的 token、labels 和 mask 与设计完全一致；
- 相同 checkpoint 和评测配置能够复现相近结果；
- 实验配置、数据版本、随机种子和 GPU-hours 能够被完整记录。

只有满足这些条件后，才进入大规模实验。

## 5. 阶段 1：从 Base 模型建立指令能力

**优先级：P0。**

### 5.1 核心问题

这一阶段需要区分三种不同收益：

- **接口对齐**：模型学会理解指令、使用对话格式并适时停止；
- **能力激发**：模型学会在合适的场景调用预训练阶段已有的能力；
- **能力获得**：模型通过 SFT 学到了原本没有掌握的知识或技能。

### 5.2 首轮实验矩阵

以下 token 数仅作为起始参考，可以根据数据和训练成本调整：

| 配置 | 训练数据 | 主要目的 |
| --- | --- | --- |
| B0 | 不训练的 Base 模型 | 建立起点 |
| B1 | 5M 高质量回答 token | 观察少量数据能否建立基本指令行为 |
| B2 | 20M 高质量回答 token | 观察规模增长收益 |
| B3 | 80M 高质量回答 token | 观察收益是否开始饱和 |
| B4 | 20M 未严格过滤的数据 | 在相同 token 预算下研究数据质量 |
| B5 | 20M 少任务、高重复数据 | 研究重复训练与任务覆盖度 |
| B6 | 20M 多任务、高多样性数据 | 研究数据多样性 |
| B7 | 官方 Instruct 模型 | 提供参考结果 |

数据规模、质量和多样性应分开研究，避免一次同时改变多个因素。例如，比较数据质量时应保持训练 token 数和任务覆盖尽可能一致。

### 5.3 评测方式

Base 模型应采用两套评测协议：

1. 符合 Base 模型使用习惯的 completion 或 few-shot 评测；
2. 与部署场景一致的聊天式 instruction 评测。

如果聊天式指令评测显著提升，而 completion 形式的任务能力变化较小，说明主要收益更可能来自接口对齐和能力激发。若模型在未见任务、跨表达方式和分布外测试中也稳定提高，才能更有把握地认为发生了能力获得或泛化增强。

### 5.4 阶段产物

- 数据规模与指令遵循能力的 scaling curve；
- 相同 token 预算下的数据质量和多样性对比；
- Base、自己训练的模型与官方 Instruct 模型的完整结果表；
- 对接口对齐、能力激发和能力获得的案例分析。

## 6. 阶段 2：研究 SFT 的训练机制

**优先级：P0。**

阶段 2 使用阶段 1 中表现稳定的数据配置，每次只研究一类变量，避免直接进行规模庞大的全因子组合。

### 6.1 数据重复与覆盖度

在相同训练 token 预算下比较：

- 重复训练一小批高质量样本；
- 持续加入不同的新样本；
- 少数任务的大量同质数据；
- 多任务、多难度和多表达方式的数据。

该实验用于判断收益主要来自更多优化步数，还是来自更广的数据覆盖。

### 6.2 Loss 设计

对比以下配置：

- 只监督 assistant 回答与监督完整序列；
- 对所有有效 token 取平均与先按样本取平均；
- 是否监督 assistant 起始 token；
- 是否监督结束 token；
- 多轮对话中监督全部 assistant 回答与只监督最后一轮回答。

重点观察训练稳定性、长短回答权重、格式遵循、停止行为和通用能力变化。

### 6.3 优化动力学

扫描低、中、高三个学习率以及不同训练轮数，并按固定训练 token 间隔保存 checkpoint。对每个 checkpoint 同时记录：

- 训练和验证 loss；
- 指令遵循能力；
- 目标任务能力；
- 通用能力；
- 回答长度和格式合规率。

重点验证 benchmark 最优点是否早于训练 loss 最低点，并据此制定 early stopping 规则。

### 6.4 全参数微调、LoRA 与 QLoRA

比较时应保持数据、训练 token 和评测配置一致，但允许不同方法分别选择合理的学习率。记录：

- 最终效果和收敛速度；
- 通用能力回退；
- 峰值显存和训练吞吐；
- checkpoint 大小和部署复杂度；
- 达到指定目标分数所需的 GPU-hours。

LoRA 限制了可训练参数数量，但不保证不会发生能力遗忘，必须通过评测验证。

## 7. 阶段 3：领域 SFT

**优先级：P1。**

### 7.1 领域选择

第一轮优先选择数学或代码等可自动验证的领域。与开放问答相比，这些领域的评测噪声更低，更容易判断提升是否真实。

### 7.2 实验矩阵

从同一个 Instruct checkpoint 出发，对比：

| 配置 | 数据或方法 | 研究问题 |
| --- | --- | --- |
| D0 | 不训练 | 领域能力起点 |
| D1 | 真实领域数据 | 真实数据的直接收益 |
| D2 | 未过滤合成数据 | 教师生成数据的基础效果 |
| D3 | 经过规则或执行验证的合成数据 | 数据正确性过滤的价值 |
| D4 | 只监督最终答案 | 最短监督路径 |
| D5 | 监督推理过程和最终答案 | 推理过程监督的影响 |
| D6 | Prompt 或 few-shot | 判断是否必须训练 |
| D7 | RAG 或领域继续预训练 | 判断任务是否更适合其他范式 |

推理过程更长或更像教师，并不自动意味着推理能力更强。应分别评估最终答案正确率、过程有效性、回答长度和分布外泛化。

### 7.3 泛化评测

领域评测至少包含：

- 与训练数据同分布但严格隔离的测试集；
- 来自不同数据源的测试集；
- 更高难度或不同题型的测试集；
- 对原题进行语义等价改写的测试集；
- 通用能力和指令遵循保留集。

只在同源 benchmark 上提高，可能来自格式适配、题型记忆或数据污染；跨数据源仍有提升，才更接近真正的领域泛化。

### 7.4 SFT、继续预训练与 RAG

- 在原始领域文本上预测全部 token，属于领域继续预训练，而不是指令 SFT；
- 在领域指令和目标回答上做 teacher forcing，属于领域 SFT；
- 需要更新、引用和追溯的事实知识，通常更适合 RAG；
- 可以进一步比较继续预训练、SFT、继续预训练后 SFT，以及 RAG 四种方案。

## 8. 阶段 4：能力跷跷板与持续学习

**优先级：P1。**

### 8.1 问题定义

该问题应被定义为“领域能力增益—通用能力保持”的双目标优化，而不是只寻找领域 benchmark 分数最高的配置。

严格来说，单次领域训练后其他能力下降可以称为负迁移或能力跷跷板；灾难性遗忘通常更强调连续学习新任务后，旧任务能力显著丢失。

### 8.2 核心对照组

| 配置 | 方法 | 目的 |
| --- | --- | --- |
| F0 | 不训练 | 建立起点 |
| F1 | 仅领域数据，全参数微调 | 观察最大领域适配和能力回退 |
| F2 | 仅领域数据，LoRA | 研究参数受限更新 |
| F3 | 90% 领域数据 + 10% 通用回放 | 低比例回放 |
| F4 | 70% 领域数据 + 30% 通用回放 | 中比例回放 |
| F5 | 50% 领域数据 + 50% 通用回放 | 高比例回放 |
| F6 | 领域 SFT + 参考模型 KL 约束 | 研究输出分布约束 |
| F7 | 通用数据训练相同步数 | 排除单纯继续优化造成的变化 |
| F8 | 训练后权重插值或模型合并 | 研究训练后的能力折中 |

### 8.3 两种预算口径

回放实验必须分别说明使用哪种口径：

1. **固定总训练 token**：计算预算公平，但通用数据会挤占领域数据；
2. **固定领域 token 曝光量**：能直接观察回放是否减少遗忘，但总计算量会增加。

两种口径回答的问题不同，不应混在同一张结果表中直接比较。

### 8.4 结果表达

每个 checkpoint 至少报告：

- 目标领域相对起始模型的提升；
- 每个通用任务相对起始模型的变化；
- 通用任务中的平均退化和最坏退化；
- 发生明显退化的任务数量；
- 训练成本。

以领域提升为一个坐标、通用能力下降为另一个坐标绘制 Pareto 前沿。不要用某些任务的提升抵消另一些任务的严重退化。

沿训练轨迹评测通常比只看最终 checkpoint 更有价值。一个常见现象是领域能力较早达到峰值，继续训练只会降低训练 loss 并加剧通用能力回退。

## 9. 阶段 5：扩展专题

**优先级：P2。**

以下专题在阶段 0 到阶段 4 稳定后按需开展。

### 9.1 多领域和训练顺序

比较领域 A 与领域 B 的：

- A、B 分别训练；
- A+B 联合训练；
- A→B 顺序训练；
- B→A 顺序训练。

每个阶段都重新评测所有已学领域，形成领域间的促进和干扰矩阵。

### 9.2 Chat template 鲁棒性

比较单一模板训练与多种语义等价模板增强，在未见模板、不同 system prompt 和指令改写上测试。该实验用于判断模型学会的是任务本身，还是某个固定模板。

### 9.3 单轮与多轮对话

在相同目标 token 预算下比较纯单轮数据和单轮、多轮混合数据，测试：

- 跨轮指代；
- 对前序约束的保持；
- 用户纠错后的响应；
- system、user 和 assistant 指令冲突；
- 只监督最后一轮与监督全部 assistant 轮次的差异。

### 9.4 结构化输出与工具调用

评价指标应从文本相似度转向：

- JSON 解析成功率；
- Schema 合法率；
- 工具选择准确率；
- 参数填写准确率；
- 工具真实执行成功率；
- 未见工具和未见 Schema 上的泛化能力。

### 9.5 拒答、校准与自我纠错

加入不可回答、前提错误和信息不足的样本，观察错误自信率、覆盖率和过度拒答。此类数据比例过高可能使模型形成普遍拒答倾向，因此需要做比例消融。

### 9.6 长上下文 SFT

在相同训练 token 预算下改变样本长度及关键信息位置，测试模型是否能利用长上下文，而不仅仅是支持更大的 context window。

## 10. 阶段 6：蒸馏专题

**优先级：P3，暂缓。**

后续应单独区分：

- 教师生成固定答案、学生做交叉熵训练：sequence-level distillation，也可视为合成数据 SFT；
- 学生拟合教师 logits 或概率分布：logit knowledge distillation；
- 学生在线采样、教师针对学生当前输出提供反馈：更接近 on-policy distillation；
- 使用 chosen/rejected 相对损失：偏好优化；
- 根据生成结果的奖励更新策略：强化学习。

是否使用 logits 或 log-prob 并不能单独决定一种方法是不是在线策略蒸馏，关键在于训练样本来自固定数据集，还是来自学生当前策略。

## 11. 推荐的实际执行顺序

### 第一轮：验证流水线

1. 使用小模型完成小样本过拟合；
2. 检查 chat template、labels、loss mask 和结束 token；
3. 跑通保存、恢复和统一评测。

### 第二轮：建立 Base 到 Instruct 基线

1. 选择一个 7B 或 8B Base 模型；
2. 完成 5M、20M 和 80M 回答 token 的规模实验；
3. 在 20M token 下比较数据质量、多样性和重复率；
4. 与未训练 Base 和官方 Instruct 模型比较。

### 第三轮：理解训练机制

1. 比较 assistant-only loss 与全序列 loss；
2. 比较 token 平均与样本平均；
3. 扫描学习率和训练轮数；
4. 比较全参数微调与 LoRA；
5. 根据中间 checkpoint 确定 early stopping 规则。

### 第四轮：领域增强

1. 选择一个可自动验证的领域；
2. 比较真实、未过滤合成和验证后合成数据；
3. 比较最终答案监督与推理过程监督；
4. 在同分布、跨数据源和改写测试集上评估。

### 第五轮：研究能力保持

1. 建立领域纯训练基线；
2. 扫描通用回放比例；
3. 比较 LoRA、KL 约束和训练后权重插值；
4. 绘制领域收益与通用退化的 Pareto 前沿；
5. 对 Pareto 前沿上的候选配置运行 3 个随机种子。

### 第六轮：跨规模验证

1. 选择前述实验中最重要的两到三个结论；
2. 在 14B 模型上复现；
3. 判断结论是普遍规律，还是特定模型规模和数据配置下的现象。

完成以上六轮后，再选择阶段 5 中的专题深入研究。

## 12. 每个实验的记录模板

每次实验至少记录：

| 字段 | 内容 |
| --- | --- |
| 实验编号 | 唯一且稳定的编号 |
| 研究问题 | 本实验希望回答的问题 |
| 可证伪假设 | 什么结果支持或否定假设 |
| 唯一主要变量 | 本轮主动改变的因素 |
| 固定变量 | 模型、模板、数据预算、解码和评测设置 |
| 训练数据 | 来源、版本、哈希、样本数和有效回答 token 数 |
| 训练配置 | 学习率、batch、epoch、优化器、精度和并行策略 |
| 计算成本 | GPU 数量、GPU-hours、峰值显存和吞吐 |
| 中间 checkpoint | 保存位置及对应训练 token 数 |
| 主要结果 | 目标能力、通用能力、指令遵循和效率 |
| 统计信息 | 随机种子、均值、方差和置信区间 |
| 异常与失败 | NaN、格式错误、数据问题和评测异常 |
| 结论与下一步 | 是否支持假设，以及下一轮实验如何调整 |

## 13. 阶段性里程碑

- **M1：流水线可信**。能够证明模板、mask、训练和评测均符合设计。
- **M2：建立指令能力**。得到 Base 到 Instruct 的数据规模、质量和多样性曲线。
- **M3：理解训练机制**。明确 loss、优化强度和参数更新方式的影响。
- **M4：获得领域增益**。在隔离测试集和分布外测试集上得到可靠提升。
- **M5：控制能力回退**。得到领域收益与通用能力保持的 Pareto 前沿。
- **M6：跨规模复现**。至少一个关键结论在不同模型规模上成立。

达到 M5 后，可以认为已经形成较完整的 SFT 理论理解和实践闭环；达到 M6 后，才更有把握把实验结论总结为可迁移的方法论。
